### 핵심 발견

**1. 과제 목록의 형태가 다섯 가지다.** 고정 표를 강제하면 빈칸을 일반론으로 채운다.

| 형태 | 예 | 기술 추적 가치 |
|---|---|---|
| 연구과제 표(상태·기간·사업화·파트너 포함) | 삼성SDI, 에코프로비엠, 한솔케미칼, 비나텍, 현대건설, 레인보우 | 높음 — 단계 판정 근거가 과제별로 있다 |
| 제품·장비 출시 목록 | 삼성전자, 삼성전기, 한미반도체, 인바디, CJ제일제당, 더존 | 장비·부품은 공정 용어라 쓸 만, SW는 브랜드명이라 약함 |
| 파이프라인·인허가 | 제약·바이오 ①~⑩ 서식, 의료기기 제품×국가×인허가 표(뷰노) | 높음 — 인허가·임상 단계가 곧 사업화 단계 |
| 대규모 상세표(XII) | 현대차, NAVER(321건), NC(약 60건, 연도·상태 없음) | 높음. 다만 행 수 폭증 |
| 없음·보안 미기재 | 삼보모터스, 코스맥스, 한화에어로스페이스 방산("보안관계상 기재하지 않습니다") | 절 밖에서 찾아야 함 |

**2. R&D 신호가 흩어져 있고, 일부는 지금 구역 추출(I·II·XII)에서 빠진다.**
- 빠지는 곳: **XI장**(방산 체계개발·양산 수주 공시, 건설신기술 지정, 로봇 연구개발 수주),
  **IV장**(삼성전기 유리 패키지 기판, 한컴 AI 조직 신설), III장 주석(뷰노 정부과제 금액, 두산 개발 중 과제 — 비용 대비 넣지 않음)
- 추출 안에 있지만 흩어진 곳: 지재권이 7항이 아닌 II장 중간(현대차·기아·POSCO·한화·현대건설·두산)이나
  I장 연혁(인바디)에 있다. CJ제일제당 BIO 기술은 7항 환경 항목에만 있다

**3. 노이즈가 네 종류다.**
- 6항 「경영상 주요계약」이 부동산·지분·종속회사 공사(현대차·현대제철·CJ 리비아 대수로·NC 사옥)인 경우.
  **반대로 기술도입·라이선스 계약이라 핵심인 경우도 있다**(두산 Ceres SOFC, HD현대중공업 GTT·MAN) — 일괄로 버리면 안 된다
- 사내 전산 과제(SK브로드밴드 메신저 구축, 현대엔지니어링 RPA)
- 매년 복사된 낡은 과제(주성엔지니어링 2001~2004년 과제, 연도 열 없음)
- 지주형 연결의 자회사 과제 혼입(두산 상세표의 약 90%가 밥캣, 한화·SKT) — 누가 하는 일인지 흐려진다

**4. 항목별 존재율.** 연구개발비 3개년·비율은 거의 전부 있다. 인력은 중소 바이오·로봇·삼보(팀별)뿐,
정부과제 **목록**은 바이오·로봇·뷰노·현대건설(국책 비고)뿐이다. 없는 곳에 요구하면 "-"만 늘거나 지어낸다.

**5. 특허 건별 목록이 34건 중 14건**에 있고, 그중 6건은 "상용화 여부·적용제품" 열이 있다
(LG엔솔·LG화학·비나텍·주성·레인보우·현대건설) — 특허를 사업화 신호로 바로 쓸 수 있다.

**6. 중소기업 보고서는 짧다.** 상보는 I+II가 1.7만 자로 멀쩡한데 구역 추출 최소 길이(2만)에 걸려 실패, 삼보는 1.9만 자로 겨우 통과.

## 2. 작업 B — R&D 프롬프트 개정 (`seed_prompts.py`의 rnd)

업종 메타데이터가 없다) **"원문에 그 서식이 있을 때만"** 조건부 절로 둔다. 없으면 절 자체를 생략하게 한다.

### 검증 (실시간 3.8-flash LOW, 34건)
- 코드 대조 지표
  - 정부과제 행 수 = 원문 목록 수 (HLB제약 15, 바이오솔루션, 뷰노 41, 레인보우 8)
  - 특허 건별 행이 원문 번호와 일치 (비나텍·주성·더존·레인보우)
  - 보안 미기재 표기(한화), 연도 없는 과제가 당기로 둔갑하지 않음(주성)
  - 노이즈 부재: 「리비아」「대수로」(CJ), 부동산·사옥(현대차·NC), 사내 메신저(SKT)
  - 끊김 0건, 출력 토큰 분포(최대가 36,864의 70% 이내), 행 상한 작동(NAVER)
- 전/후: 기존 프롬프트 대비 기술 종합 보고서 단계 판정 근거 수(전고체·세포유전자)
- 비용: 34건 실시간 약 $3

### 반복 생성 일관성 (같은 입력 2회)
LLM은 입력이 같아도 출력이 달라진다. 조건부 절이 많은 이번 개정은 **같은 보고서에서 절이 나왔다 안 나왔다
하는 것**이 가장 큰 위험이다(기존 실측: 종속회사 행 수가 회차마다 12~166행, 기술 보고서 단계 판정 흔들림).

- **표본 8건 × 2회 × 프롬프트 전/후** — 형태별로 하나씩, 흔들리기 쉬운 경우 위주

  | 표본 | 보는 것 |
  |---|---|
  | 뷰노 | 정부과제 41행·인허가 표가 두 번 다 같은가 |
  | HLB제약 | 파이프라인 절 |
  | 현대건설 | 과제 약 122건 — 행 선택·국책 비고 |
  | NAVER | 321건 — 60행 상한에서 **어느 행을 고르는지** |
  | 한화에어로스페이스 | 보안 미기재 표기, XI 수주 |
  | 주성엔지니어링 | 연도 없는 옛 과제 처리 |
  | CJ제일제당 | 노이즈(리비아 공사) 배제, BIO 편중 표시 |
  | 에코프로비엠 | 과제 상태(진행중/완료) |

- **지표 (코드로 잰다)**

  | 지표 | 기준 |
  |---|---|
  | 절 구성(조건부 절 유무·목록의 성격 라벨) | 2회 **완전 일치** |
  | 연구개발비 표 숫자 | **완전 일치** |
  | 정부과제·특허 건별 행 수 | 완전 일치, 원문 목록 수와도 일치 |
  | 과제명 집합 겹침(정규화 후 Jaccard) | ≥ 0.9 |
  | 공통 과제의 상태 값 일치율 | ≥ 95% |
  | 기술 사업화 동향 항목 겹침 | ≥ 0.8 |

- **기준 미달 시 처방 순서**: ① 흔들리는 규칙을 결정적으로 바꾼다(예: 행 선택 기준을 "원문 순서 앞에서부터"로 고정,
  라벨 판정 조건을 원문 문구로 못박기) ② 그래도 흔들리는 값은 코드가 채운다(기술 종합 보고서 표 틀처럼)
  ③ temperature를 낮추는 것은 마지막에 같은 표본으로 비교해 본 뒤 정한다(Gemini 3 계열은 기본값 권장이라 부작용 확인 필요)
- **전 프롬프트도 2회** 돌려 개정 전 흔들림을 기준선으로 둔다 — 개정이 흔들림을 늘렸는지 구분하려면 필요하다
- 비용: 8건 × 2회 × 2프롬프트 = 32회, 실시간 약 $3
- 기술 종합 보고서까지 이어지는 영향은 전고체·세포유전자 2개 기술로 분석 2벌 각각 보고서를 만들어 단계 판정이 같은지 본다(추가 4회, 약 $0.2)
